# Folio

Folio is a premium, distraction-free Android ebook reader by MakeMission LLC (`com.makemission.folio`). It bridges digital convenience and the tactile craft of traditional bookmaking — fluid stylus interactions, magazine-quality typography, and adaptive layouts for phones and tablets.

Jetpack Compose–first. Library (editorial grid + Vocabulary badge + swipe right to Settings / swipe left to Insights + pull-down search across all books' text with highlights/bookmarks priority + automatic device scanning for EPUBs in Downloads/Documents/external storage with content-hash dedup, subtle non-blocking progress, Settings toggle + manual scan, Insights teaser, long-press on cover for actions, external VIEW intent for EPUBs from Files/browser/email reusing import pipeline — no FAB), core Reading (native EPUB, adaptive layouts, Room progress + frictionless navigation + persistent “Always show progress bar” via DataStore, true-page numbers via virtual-canvas pre-computation, ambient-light adaptive contrast via WCAG 7:1 + time-aware evening warmth tinting (system-clock, gradual, editorial, palette-coordinated), Knuth-Plass orphan/widow control with squared-off paragraphs, bounding-box image expansion for diagrams, bookmarks as position-only marks distinct from highlights with single hamburger menu (Bionic/X-Ray/Contrast/Bookmarks/Search) instead of cluttered top-bar icons, contextual in-book search with same prioritization and jump-to-position, tactile + visual polish — chapter-boundary haptics, iOS-like scroll fades, premium micro-animations), stylus highlighting (zero-friction, true-ink Multiply, pressure/tilt physics, lasso extraction), bionic reading, chapter time remaining, LCS-anchored highlights, on-device X-Ray, offline dictionary (WordNet gzipped + selection Explain), spaced-repetition vocabulary (SM-2, pure on-device), a Folio-themed Settings screen (Reading/Library/Insights/Smart Features/Appearance/Support·Logs — now with 4 dark palettes + evening warmth + haptics toggle/Privacy sections) + dedicated Smart Features guide (editorial plain-English tour of 12 on-device intelligences — Bionic, time left, X-Ray, vocabulary, true pages, line breaking, anchors, contrast, diagrams, tint, search, dictionary — each with problem / fix / why, no jargon) + 4 editorial dark palettes (Folio Green default + True Black OLED, Warm Sepia, Cool Slate, all burgundy/amber coherent, DataStore-persisted, adaptive-contrast-coordinated, app-wide) + standalone Insights journal (aggregates existing Highlight, Bookmark, ReadingProgress, VocabularyCard, Book data — streaks/time patterns from timestamps, no new collection), and first-launch onboarding (pager + upfront storage/notification permissions, DataStore-tracked, privacy-first) are now in place; other algorithmic features come later.

## Tech stack

- Kotlin 2.2, Android Gradle Plugin 9.4 (KSP via `com.google.devtools.ksp`; version catalog in `gradle/libs.versions.toml`)
- `compileSdk` / `targetSdk` 37, `minSdk` 33, Java 17
- Jetpack Compose (BOM `2025.09.00`): `ui`, `foundation`, `material3`, `activity-compose`
- Navigation Compose 2.8.4 (`navigation-compose`), lifecycle `viewmodel-compose` / `runtime-compose`
- Room 2.7.2 (`room-runtime`, `room-ktx`, KSP `room-compiler`) for books, progress, highlights + bookmarks + vocabulary (v8 — SM-2 vocabulary + scan dedup hash/path + bookmarks)
- DataStore Preferences 1.1.1 (`androidx.datastore:datastore-preferences`) for user settings (e.g. “Always show progress bar”, `hasSeenOnboarding`, `autoScanEnabled`, `hapticsEnabled`, `darkPalette`, `timeTintEnabled`)
- Debug logging: `data/logging/FolioLogger.kt` + `FolioApp` — local rolling file `filesDir/logs/folio.log` (256 KB cap, trimmed half when full), `FolioApp` installs `UncaughtExceptionHandler`, no network; `LogsScreen` views/exports via `FileProvider` + share sheet
- EPUB parsing: native ZIP + `org.jsoup:jsoup:1.18.3` (no network/AI — §6), cover extraction via OPF manifest; PDF plug-in point noted in `EpubScanner`/`EpubParser` (not implemented)
- Offline dictionary: bundled `assets/dictionary.json.gz` (WordNet 3.0-derived, CC-BY permissive, 12k common lemmas, 113 KB gz / 1.37 MB json, vs 150k full WordNet ~3.2 MB gz / 12 MB json) via `DictionaryRepository` (GZIP streaming, phrase-aware, no network) — curated subset tradeoff documented below
- On-device search: `data/search/SearchRepository.kt` — local phrase search across title/author/paragraphs + Room highlights/bookmarks, no network, highlights/bookmarks ranked first
- Coil 2.7.0 (`io.coil-kt:coil-compose`) for cover images
- EPUB intake — no manual "+" FAB; automatic device scanning (Downloads/Documents/external via `EpubScanner` + MediaStore, hash/path dedup, reuse of same private-copy→parse→Room pipeline) plus external `ACTION_VIEW` intent filter (`application/epub+zip`, `*/*` with `.epub` pathPattern) so Folio appears when opening `.epub` from Files / browser / email — handled in `MainActivity` (`singleTop` + `onNewIntent`) reusing `LibraryViewModel.importEpub` pipeline
- Material Components (`Theme.Material3.DayNight.NoActionBar` for the window)
- Design system in `ui/theme/` — see below

## Design system

## Library screen (editorial grid — no FAB, long-press, swipe both ways)

`LibraryScreen` + `LibraryViewModel` — inspired by `book-story-master`'s `LibraryScaffold` →
`LibraryGridLayout` layering, rebuilt for Folio (now without manual "+" FAB — intake via auto-scan + external VIEW):

- **Curated grid** — `LazyVerticalGrid` with `GridCells.Adaptive(148.dp)` so phones show 2 columns and tablets scale naturally; each item is a `BookCoverCard` (2:3 cover, rounded 16dp, spine accent, Folio title chip, cover image via Coil when available). Cards are clickable and navigate to the Reader.
- **Empty state** — centered flat illustration (amber sun, burgundy / paper / deep-green books on a shelf) drawn with Compose `Canvas`, plus editorial copy. Shown when both imported and curated are empty (curated ensures the grid is never empty before first import).
- **Intake — no FAB (§6)** — The manual "+" FAB has been removed entirely. Intake is now only via (a) automatic device scanning (see below) and (b) external `ACTION_VIEW` (`MainActivity` `singleTop` + `onNewIntent` + intent-filter for `application/epub+zip` / `*/*` + `.epub` pathPattern) so Folio appears when opening `.epub` from Files / browser / email; the `View` uri is passed to `LibraryViewModel.importEpub(uri, context)` reusing the *same* private-copy→parse→cover→Room pipeline as before (`persistParsedEpub` — no duplication). Invalid/corrupted EPUBs show a Snackbar and do not crash.
- **Automatic device scanning (§6 — EPUB only, PDF plug-in point)** — `LibraryViewModel.scanDevice()` + `data/scan/EpubScanner.kt`: on app launch (when `SettingsRepository.autoScanEnabled` is true and storage permission was granted during onboarding) and via a manual **Scan device** button in Settings, searches common storage locations (Downloads, Documents, general external storage via `Environment` + `MediaStore.Files` best-effort, `MAX_FILES=80`, `MAX_DEPTH=4`) for `.epub` files. Uses the storage permission already requested during onboarding; if permission was denied the feature is simply unavailable/disabled (no crash, no repeated prompt, manual SAF import still works). For each found file not already in the library, reuses the **same** private-storage copy → `EpubParser` → `BookEntity` pipeline as manual import (shared `persistParsedEpub`, no logic duplication) — with deduplication by **file content (SHA-256 `fileHash`)** and **filename/path tracking (`importedFromPath`)**, plus legacy private-file hash fallback, so no duplicate `Book` entries. PDF parsing doesn't exist yet; `EpubScanner` documents the plug-in point (add `pdf` to the extension check in `walkDir` and the `MediaStore` `DISPLAY_NAME LIKE %.pdf` selection, then route to a future `PdfParser`). Structural inspiration from `book-story-master`'s `BrowseScanOption`/`FileSystemRepository` only.
- **Scan progress (non-blocking)** — `LibraryViewModel.isScanning`/`scanProgress` (`StateFlow`) drives a subtle loading state on the Library screen: a compact `Card` with `CircularProgressIndicator` + `LinearProgressIndicator` and text like “Scanning 3/12 · 1 new” between the `VocabularyTeaser` and the grid, plus a `Snackbar` result (“Scan complete: 2 new book(s)…”). Does not block the UI or cover the grid (`viewModelScope` + `Dispatchers.IO`).
- **Settings toggle** — `SettingsRepository.KEY_AUTO_SCAN_ENABLED` (`autoScanEnabled` `Flow<Boolean>` default true) persisted via the same `folio_settings` DataStore. The **Library** section in `SettingsScreen` has a `Switch` for “Auto-scan on launch” (disabled when permission not granted) and a **Scan device** `Button` (disabled when permission denied or already scanning, shows `CircularProgressIndicator` while scanning). The toggle and button share the activity-scoped `LibraryViewModel` so progress/snackbar are unified; no extra DataStore or navigation rewrite.
- **Grid update + long-press actions** — `LibraryViewModel.books` is `bookDao.observeAll().map { imported + curatedSampleBooks() }` (`SharingStarted.Eagerly` with initial `curatedSampleBooks()` so the 8 curated covers show instantly) so imported (and auto-scanned) books appear first in the grid alongside the curated samples; covers show the extracted image when present. `BookGrid` / `BookCoverCard` now use `combinedClickable` — tap opens `ReadingScreen`, **long-press** ( `ExperimentalFoundationApi` ) opens `LibraryBookActionsSheet` ( `ModalBottomSheet` ) with actions for that `Book`: **Remove from library** (deletes `BookEntity` + private `books/<id>_` file + `covers/<id>` + `ReadingProgress`/`Highlight`/`Bookmark`/`XRayCache`, disabled for curated samples with "Curated sample — can't be removed"), **Book info** (`AlertDialog` with title/author/id/file/cover), **Reset progress** (`ReadingProgressDao.clear`), and Close — all reuse existing `BookDao`/`ReadingProgressDao`/`HighlightDao`/`BookmarkDao`/`XRayCache` without new logic.
- **Vocabulary teaser (§5 — SM-2, non-intrusive)** — a discreet `Card` below the header shows due-for-review count (`LibraryViewModel.dueVocabularyCount` via `VocabularyDao.observeDueCount()`). When `dueCount > 0` a small amber badge displays the number; otherwise it shows “No words due — keep reading” with an `Open` button. Tapping navigates to the `Vocabulary` review screen (`FolioNav` `vocabulary` route). No reading popups or interruptions — the badge surfaces only on the Library screen.
- **Insights teaser (journal, not dashboard)** — a second discreet `Card` (“Insights — A quiet ledger of your reading”, `surface` with amber dot, `InsightsTeaser`) below the vocabulary card; tapping opens `FolioRoute.Insights`. Same editorial style, read-only aggregation, empty-state aware.
- **Pull-down search (on-device, not pull-to-refresh)** — `LibraryScreen` + `LibraryViewModel` + `data/search/SearchRepository.kt`: pulling down on the Library (vertical drag >80px via combined `pointerInput` + `awaitPointerEventScope`, or tap “⌕ Search” in the header for accessibility) reveals a search bar with standard pull-to-reveal pattern (not pull-to-refresh). Typing a phrase debounces 280ms (`distinctUntilChanged`) and queries **on-device only**: `SearchRepository.searchLibrary(query, context)` scans all imported books' parsed EPUB text (via cached `EpubParser` chapters) + title/author (`BookEntity` `contains(..., ignoreCase)`) + full-text phrase matching (`paragraph.lowercase().contains(qLower)`) with snippet extraction (±40 chars). Results prioritize **highlights/bookmarks first** (`MatchType.HIGHLIGHT`/`BOOKMARK` `rank 0`), then title/author (`rank 1`), then general text (`rank 2`), sorted by `rank` then title/chapter/paragraph, capped at `MAX_RESULTS=40` (`MAX_PER_BOOK=6`). Tapping a result navigates via `FolioNav.Reader.create(bookId, title, ch, para)` → `ReadingScreen(initialChapterIndex, initialParagraphIndex)` and jumps directly to the phrase using existing bookmark flat-index logic (`flatIndexForBookmark`/`flatIndexForBookmarkInLeft/Right`) — reuse, don't duplicate. No network search, just local `EpubParser` + Room `HighlightDao.getForBook`/`BookmarkDao.getForBook`. Graceful no-results: on-brand messaging (“No passages found for “X” — Try a different phrase — Folio searches titles, authors, and the text you’ve saved, all on-device.” with amber sun + “Clear search”). Structural inspiration from `book-story-master`'s `BrowseModel` search/debounce only.
- **In-book search (contextual, on-device)** — `ReadingScreen` + `ReadingViewModel` (same `SearchRepository.searchInBook`, debounced 260ms, highlights/bookmarks `rank 0` first): top-bar “⌕” toggles a contextual search bar (`OutlinedTextField` + `CircularProgressIndicator`/`Clear`/`Close`) with helper “On-device — highlights & bookmarks first, then text.” Results shown directly below as a `Card` with `LazyColumn` (`220.dp`) listing up to `40` passages for the current book (chapter/paragraph `Snippet` + `Highlight`/`Bookmark`/`Text` badge, amber when priority), or graceful no-results (“No passages found… Try a different phrase — Folio searches highlights, bookmarks and text, all on-device.”). Tapping jumps via unified `pendingSearchJump` `LaunchedEffect` (phone `singleListState`, tablet `leftListState`/`rightListState` + mid-split, same `flatIndexForBookmark*` helpers as bookmarks/Library) without duplicating jump logic. Keeps search on-device — no network.
- **Library gestures — Settings + Insights** — Swipe **right** on the Library (horizontal drag >120px via combined `pointerInput` with per-gesture `hasNavigated` debounce, or tap “⚙ Settings” in the header) navigates via `FolioNav` `settings` route (`launchSingleTop = true` so one swipe = one push). **Swipe left** (< -120px, `|dx|>|dy|`) navigates to `Insights` (`launchSingleTop`) as an additional entry point — the existing Insights teaser card is kept, not removed, so there are now two ways in (teaser + swipe). Both gestures use the same `hasNavigated` debounce and coexist with the vertical `LazyVerticalGrid` scroll (only `|dx|>|dy|` consumes). Built on top of existing `FolioNavHost` (added `FolioRoute.Settings`/`Insights`) — not a rewrite; structural inspiration from `book-story-master`’s settings navigation only.
- **Header** — weighty sans "Library" title + collection subtitle over the Folio background, now a `Row` with “⌕ Search” + “⚙ Settings” `TextButton`s for discoverability.

## Insights screen (quiet ledger, read-only aggregation)

`InsightsScreen` + `InsightsViewModel` (`ui/insights/`) — per spec, a book-themed journal not a fitness dashboard. **Read-only**: `combine`-s `BookDao.observeAll`, `HighlightDao.observeAll`, `BookmarkDao.observeAll`, `ReadingProgressDao.observeAll`, `VocabularyDao.observeAll` — no parallel tracking, queries what already exists (§6). Derives simple, thoughtful stats: **Shelf** (total books / in-progress via `reading_progress` rows), **Marginalia** (total highlights / bookmarks), **Lexicon** (SM-2 `VocabularyCard` → total / due `dueAt<=now` / mastered `repetitions>=3||interval>=21` / learning), **Rhythm** (reading `lastReadMillis` → `LocalDate` distinct days, `currentStreak`/`longestStreak` consecutive-day math via `ChronoUnit.DAYS`, `lastReadLabel` “today/yesterday/Nd ago”, sessions count). Empty state gracefully shows an `EmptyJournalCard` with encouraging on-brand copy (“No pages turned yet — and that’s fine … open a book … Folio keeps everything on-device”). FolioTheme styling: `background` deep green, `surface` cards `16dp` + `1dp` elevation, editorial uppercase `labelMedium` + `headlineMedium` values + small amber `Canvas` dot, `SettingsSection`-like hero (`InsightsHero` journal Canvas) — no generic charts/graphs. Accessible from **Settings → Insights** (`Button("Open Insights")` in `Insights` section) and **Library → Insights teaser** (`InsightsTeaser` card below vocabulary). Built on `Navigation` `FolioRoute.Insights`, no rewrite of existing DAOs (only added `observeAll`/`count` queries as read-only extensions). Inspiration from `book-story-master`’s stats/history grouping only.

## Smart Features screen (editorial guide, plain English, thoughtful — not a changelog)

`SmartFeaturesScreen` (`ui/settings/SmartFeaturesScreen.kt`) — accessible via **Settings → Smart Features** (`SettingsScreen` new `Smart Features` section with “Meet the twelve” button, `onSmartFeaturesClick` → `FolioRoute.SmartFeatures` new destination on top of existing `FolioNavHost`, no rewrite). Feels like a thoughtful booklet, not marketing. Structural inspiration from `book-story-master`’s info/settings lists only.

## Debug logging (bug-fix support, on-device, rolling, shareable)

`data/logging/FolioLogger.kt` + `FolioApp` + `ui/settings/LogsScreen.kt` — built on top of existing Settings, not a rewrite. Captures key app events useful for debugging: import failures (SAF copy/parse), EPUB parsing issues (`EpubParser` null/cover), device scan progress/dedup, reading load/X-Ray/LCS/progress/bookmark/highlight/vocabulary/search failures, and uncaught crashes via `Thread.setDefaultUncaughtExceptionHandler` installed in `FolioApp.onCreate`. Single-thread executor for file I/O, 256 KB rolling cap (`filesDir/logs/folio.log` — when over, keeps most recent half, no unbounded growth), `SimpleDateFormat` timestamp + `[LEVEL] [Tag] message | stack` lines, `MAX_MESSAGE_LEN 2000` truncation. Requests storage/file access (`READ_EXTERNAL_STORAGE` / `READ_MEDIA_IMAGES|VIDEO|AUDIO` on Tiramisu) for EPUB import / future auto-scan and `POST_NOTIFICATIONS` (Tiramisu+) for future features via `rememberLauncherForActivityResult(RequestMultiplePermissions/RequestPermission)` with `ContextCompat.checkSelfPermission` checks, status UI (`Granted`/`Not granted`), and graceful denial handling (manual SAF import via + still works, notifications silent, “Skip”/“Get started” always enabled). Built on top of existing `FolioNavHost`/`FolioTheme` — not a rewrite; structural inspiration from `book-story-master`’s `StartScreen` (pager + sections) only.
