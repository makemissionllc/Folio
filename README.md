# Folio

Folio is a premium, distraction-free Android ebook reader by MakeMission LLC (`com.makemission.folio`). It bridges digital convenience and the tactile craft of traditional bookmaking — fluid stylus interactions, magazine-quality typography, and adaptive layouts for phones and tablets.

Jetpack Compose–first. Library (editorial grid + Vocabulary badge + swipe right to Settings / swipe left to Insights + pull-down search across all books' text with highlights/bookmarks priority + automatic device scanning for EPUBs in Downloads/Documents/external storage with content-hash dedup, subtle non-blocking progress, Settings toggle + manual scan, Insights teaser, long-press on cover for actions, external VIEW intent for EPUBs from Files/browser/email reusing import pipeline — no FAB), core Reading (native EPUB, adaptive layouts, Room progress + precise paragraph-level restoration via debounced save + frictionless navigation (continuous whole-book LazyColumn vs chapter-swipe HorizontalPager per-chapter vertical, tablet spreads) + persistent “Always show progress bar” via DataStore, true-page numbers via virtual-canvas pre-computation (disk-cached via TruePageCache), ambient-light adaptive contrast via WCAG 7:1 + time-aware evening warmth tinting (system-clock, gradual, editorial, palette-coordinated), Knuth-Plass orphan/widow control with squared-off paragraphs, bounding-box image expansion for diagrams, bookmarks as position-only marks distinct from highlights with single hamburger menu (Bionic/X-Ray/Contrast/Bookmarks/Search) instead of cluttered top-bar icons, contextual in-book search with same prioritization and jump-to-position, tactile + visual polish — chapter-boundary haptics, iOS-like scroll fades, premium micro-animations, chapter-swipe HorizontalPager, palette/theme Crossfade), stylus highlighting (zero-friction, true-ink Multiply, pressure/tilt physics, lasso extraction), bionic reading, chapter time remaining, LCS-anchored highlights, on-device X-Ray (progressive per-chapter, prioritized), offline dictionary (WordNet gzipped + selection Explain), spaced-repetition vocabulary (SM-2, pure on-device), a Folio-themed Settings screen (Reading/Library/Insights/Smart Features/Appearance/Support·Logs — now with 4 dark palettes + evening warmth + haptics toggle + navigation mode Continuous/Chapter swipe + Privacy sections) + dedicated Smart Features guide (editorial plain-English tour of 12 on-device intelligences — Bionic, time left, X-Ray, vocabulary, true pages, line breaking, anchors, contrast, diagrams, tint, search, dictionary — each with problem / fix / why, no jargon) + premium editorial polish (NavHost slide+fade 340ms FastOutSlowIn, Crossfade for palette/theme, AnimatedContent for nav mode, 48dp touch targets, pleasant loading with pulsing amber dot, BookGrid stagger, chapter-title fades) + 4 editorial dark palettes (Folio Green default + True Black OLED, Warm Sepia, Cool Slate, all burgundy/amber coherent, DataStore-persisted, adaptive-contrast-coordinated, app-wide) + standalone Insights journal ## Tech stack

- Kotlin 2.2, Android Gradle Plugin 9.4 (KSP via `com.google.devtools.ksp`; version catalog in `gradle/libs.versions.toml`)
- `compileSdk` / `targetSdk` 37, `minSdk` 33, Java 17
- Jetpack Compose (BOM `2025.09.00`): `ui`, `foundation`, `material3`, `activity-compose`
- Navigation Compose 2.8.4 (`navigation-compose`), lifecycle `viewmodel-compose` / `runtime-compose`
- Room 2.7.2 (`room-runtime`, `room-ktx`, KSP `room-compiler`) for books, progress, highlights + bookmarks + vocabulary (v9 — SM-2 vocabulary + scan dedup hash/path + bookmarks with unique (bookId, chapterIndex, paragraphIndex) index, IGNORE on conflict, allows multiple bookmarks per book)
- DataStore Preferences 1.1.1 (`androidx.datastore:datastore-preferences`) for user settings (e.g. “Always show progress bar”, `hasSeenOnboarding`, `autoScanEnabled`, `booksFolderUri`, `hapticsEnabled`, `darkPalette` default **Cool Slate**, `themeMode` Light/Dark/Auto default Auto, `timeTintEnabled`, `bionicEnabled`, `adaptiveContrastEnabled` — reading toggles now persist across restarts)
- Debug logging: `data/logging/FolioLogger.kt` + `FolioApp` — local rolling file `filesDir/logs/folio.log` (256 KB cap, trimmed half when full), `FolioApp` installs `UncaughtExceptionHandler`, no network; `LogsScreen` views/exports via `FileProvider` + share sheet
- EPUB parsing: native ZIP + `org.jsoup:jsoup:1.18.3` (no network/AI — §6), cover extraction via OPF manifest; PDF plug-in point noted in `EpubScanner`/`EpubParser` (not implemented)
- Offline dictionary: bundled `assets/dictionary.json.gz` (WordNet 3.0-derived, CC-BY permissive, 12k common lemmas, 113 KB gz / 1.37 MB json, vs 150k full WordNet ~3.2 MB gz / 12 MB json) via `DictionaryRepository` (GZIP streaming, phrase-aware, no network) — curated subset tradeoff documented below
- On-device search: `data/search/SearchRepository.kt` — local phrase search across title/author/paragraphs + Room highlights/bookmarks, no network, highlights/bookmarks ranked first
- Coil 2.7.0 (`io.coil-kt:coil-compose`) for cover images
- WorkManager 2.9.1 (`androidx.work:work-runtime-ktx`) for background heavy processing — X-Ray chapter-by-chapter, ParsedBookCache (expedited + battery-aware, soon)
- EPUB intake — no manual "+" FAB; automatic device scanning (configurable SAF folder via Settings → Library or Downloads/Documents/external via `EpubScanner` + MediaStore, `MAX_DEPTH=8` with skipped-folder visibility, hash/path dedup, reuse of same private-copy→parse→Room pipeline) plus external `ACTION_VIEW` intent filter (`application/epub+zip`, `*/*` with `.epub` pathPattern) so Folio appears when opening `.epub` from Files / browser / email — handled in `MainActivity` (`singleTop` + `onNewIntent`) reusing `LibraryViewModel.importEpub` pipeline
- Material Components (`Theme.Material3.DayNight.NoActionBar` for the window)
- Design system in `ui/theme/` — see below

## Design system

The palette and typography come from `Inspiration/Folio_Project.md` §2:

- **Background** — deep green `#004F39` (library + dark mode)
- **Active / tags** — burgundy `#780116`
- **Accent** — xanthous `#F7B538` (highlights, progress, focus)

Typography: UI chrome uses the system SF-style sans (Android Roboto via `FontFamily.Default`) with **weight** hierarchy — headlines Black/Bold, titles ExtraBold/Bold/SemiBold, labels Medium/Regular — while reading body stays serif (`bodyLarge` 17/27 via `FontFamily.Serif`). See `Type.kt` (`FolioUiFamily` vs `FolioReadingFamily`). Both `Color.kt` / `Type.kt` / `Theme.kt` follow the structure of the `book-story-master` reference app's `ui/theme/` (no code copied).

## Library screen (editorial grid — no FAB, long-press, swipe both ways)

`LibraryScreen` + `LibraryViewModel` — inspired by `book-story-master`'s `LibraryScaffold` →
`LibraryGridLayout` layering, rebuilt for Folio (now without manual "+" FAB — intake via auto-scan + external VIEW):

- **Curated grid** — `LazyVerticalGrid` with `GridCells.Adaptive(148.dp)` so phones show 2 columns and tablets scale naturally; each item is a `BookCoverCard` (2:3 cover, rounded 16dp, spine accent, Folio title chip, cover image via Coil when available). Cards are clickable and navigate to the Reader.
- **Empty state** — centered flat illustration (amber sun, burgundy / paper / deep-green books on a shelf) drawn with Compose `Canvas`, plus editorial copy. Shown when both imported and curated are empty (curated ensures the grid is never empty before first import).
- **Intake — no FAB, minimal + background (§6)** — The manual "+" FAB has been removed entirely. Primary intake is (a) automatic device scanning (see below) and (b) external `ACTION_VIEW` (`MainActivity` `singleTop` + `onNewIntent` + intent-filter for `application/epub+zip` / `*/*` + `.epub` pathPattern) so Folio appears when opening `.epub` from Files / browser / email; the `View` uri is passed to `LibraryViewModel.importEpub(uri, context)` reusing the *same* private-copy pipeline but now **minimal** (`persistParsedEpub` does copy → lightweight OPF metadata (`EpubParser.extractMetadata`) → cover → Room, *no* full X-Ray/TruePage/indexing — that is scheduled via WorkManager `BookProcessingWorker` + `BookProcessingScheduler` as expedited one-time work (battery-not-low, soon) that processes chapter-by-chapter). A subtle manual fallback remains: **Settings → Library → Add book manually** (minor `TextButton` “Add…”, not a FAB) launches `ACTION_OPEN_DOCUMENT` (`application/epub+zip`, `*/*`) and reuses the same `persistParsedEpub` pipeline — no duplicated logic, just a safety net if scan or VIEW misses a file. Invalid/corrupted EPUBs show a Snackbar and do not crash.
- **Automatic device scanning (§6 — EPUB only, PDF plug-in point)** — `LibraryViewModel.scanDevice()` + `data/scan/EpubScanner.kt`: on app launch (when `SettingsRepository.autoScanEnabled` is true and storage or SAF permission is present) and via a manual **Scan device** button in Settings, scans for `.epub` files. Discovery prioritizes a user-configured books folder granted via Storage Access Framework (`ACTION_OPEN_DOCUMENT_TREE` with `DocumentFile` traversal, `takePersistableUriPermission`), with graceful fallback to common storage locations (Downloads, Documents, external storage via `Environment` + `MediaStore.Files` best-effort). `MAX_DEPTH` is set to **8** (expanded from 4 to support deeply nested book collections like author/series subfolders at depth 5), with `MAX_FILES=80`. Any folders exceeding `MAX_DEPTH` are tracked rather than silently dropped and reported to the user in scan feedback (“N folders were too deep to search”). For each found file not already in the library, reuses the **same** private-storage copy → `EpubParser` → `BookEntity` pipeline as manual import (shared `persistParsedEpub`, streaming SHA-256 computation directly from ContentResolver/File to avoid cache leaks) — deduplicated by **file content (SHA-256 `fileHash`)** and **filename/path tracking (`importedFromPath`)**, plus legacy private-file hash fallback, so no duplicate `Book` entries. PDF parsing doesn't exist yet; `EpubScanner` documents the plug-in point (add `pdf` to the extension check in `walkDir`/SAF filter and the `MediaStore` `DISPLAY_NAME LIKE %.pdf` selection, then route to a future `PdfParser`). Structural inspiration from `book-story-master`'s `BrowseScanOption`/`FileSystemRepository` only.
- **Scan progress (now silent on Library, non-blocking elsewhere)** — `LibraryViewModel.isScanning`/`scanProgress` (`StateFlow`) still drive `Scan device` in Settings (Button shows `CircularProgressIndicator` when scanning) and a `Snackbar` result, but the Library screen’s visible `Card` progress bar (previously “Scanning 3/12 · 1 new” with `CircularProgressIndicator` + `LinearProgressIndicator`) has been removed — auto-scan now runs silently in the background (no grid overlay). Manual scan still surfaces a `Snackbar` result. Does not block the UI (`viewModelScope` + `Dispatchers.IO`).
- **Settings toggle & folder picker** — `SettingsRepository.KEY_AUTO_SCAN_ENABLED` (`autoScanEnabled` `Flow<Boolean>` default true) and `KEY_BOOKS_FOLDER_URI` (`booksFolderUri` `Flow<String?>`) persisted via `folio_settings` DataStore. The **Library** section in `SettingsScreen` features:
  1. **Choose books folder**: Launches `ActivityResultContracts.OpenDocumentTree()`, persists read permission via `takePersistableUriPermission`, displays the folder name, and offers **Change** and **Clear** actions.
  2. **Auto-scan on launch**: `Switch` automatically scanning the chosen folder or common locations on startup.
  3. **Scan device**: Manual `Button` triggering immediate scan, disabled while scanning with `CircularProgressIndicator`.
  The toggle and button share the activity-scoped `LibraryViewModel` so progress/snackbar are unified; no extra DataStore or navigation rewrite.
- **Grid update + long-press actions** — `LibraryViewModel.books` is `bookDao.observeAll().map { imported + curatedSampleBooks() }` (`SharingStarted.Eagerly` with initial `curatedSampleBooks()` so the single “How to use Folio” guide shows instantly until real books arrive) so imported (and auto-scanned) books appear first in the grid alongside the built-in guide (now single, not 8 placeholders); covers show the extracted image when present. `BookGrid` / `BookCoverCard` now use `combinedClickable` — tap opens `ReadingScreen`, **long-press** ( `ExperimentalFoundationApi` ) opens `LibraryBookActionsSheet` ( `ModalBottomSheet` ) with actions for that `Book`: **Remove from library** (deletes `BookEntity` + private `books/<id>_` file + `covers/<id>` + `ReadingProgress`/`Highlight`/`Bookmark`/`XRayCache`, disabled for curated samples with "Curated sample — can't be removed"), **Book info** (`AlertDialog` with title/author/id/file/cover), **Reset progress** (`ReadingProgressDao.clear`), and Close — all reuse existing `BookDao`/`ReadingProgressDao`/`HighlightDao`/`BookmarkDao`/`XRayCache` without new logic.
- **Quick row — removed (was Vocabulary + Insights)** — Previously a subtle row below the header showed Vocabulary due and Insights ›. Now removed entirely per latest task: Library shows just the grid and search; **Vocabulary** is reachable from **Insights → Lexicon → Review Vocabulary** (or directly via `FolioNav.vocabulary` if needed), and **Insights** via swipe-left gesture or Settings → Insights. Library is now purely a bookshelf, no dashboard row. No popups.
- **Pull-down search (on-device, not pull-to-refresh)** — `LibraryScreen` + `LibraryViewModel` + `data/search/SearchRepository.kt`: pulling down on the Library (vertical drag >80px via combined `pointerInput` + `awaitPointerEventScope`, or tap “⌕ Search” in the header for accessibility) reveals a search bar with standard pull-to-reveal pattern (not pull-to-refresh). Typing a phrase debounces 280ms (`distinctUntilChanged`) and queries **on-device only**: `SearchRepository.searchLibrary(query, context)` scans all imported books' parsed EPUB text (via cached `EpubParser` chapters) + title/author (`BookEntity` `contains(..., ignoreCase)`) + full-text phrase matching (`paragraph.lowercase().contains(qLower)`) with snippet extraction (±40 chars). Results prioritize **highlights/bookmarks first** (`MatchType.HIGHLIGHT`/`BOOKMARK` `rank 0`), then title/author (`rank 1`), then general text (`rank 2`), sorted by `rank` then title/chapter/paragraph, capped at `MAX_RESULTS=40` (`MAX_PER_BOOK=6`). Tapping a result navigates via `FolioNav.Reader.create(bookId, title, ch, para)` → `ReadingScreen(initialChapterIndex, initialParagraphIndex)` and jumps directly to the phrase using existing bookmark flat-index logic (`flatIndexForBookmark`/`flatIndexForBookmarkInLeft/Right`) — reuse, don't duplicate. No network search, just local `EpubParser` + Room `HighlightDao.getForBook`/`BookmarkDao.getForBook`. Graceful no-results: on-brand messaging (“No passages found for “X” — Try a different phrase — Folio searches titles, authors, and the text you’ve saved, all on-device.” with amber sun + “Clear search”). Structural inspiration from `book-story-master`'s `BrowseModel` search/debounce only.
- **In-book search (contextual, on-device)** — `ReadingScreen` + `ReadingViewModel` (same `SearchRepository.searchInBook`, debounced 260ms, highlights/bookmarks `rank 0` first): top-bar “⌕” toggles a contextual search bar (`OutlinedTextField` + `CircularProgressIndicator`/`Clear`/`Close`) with helper “On-device — highlights & bookmarks first, then text.” Results shown directly below as a `Card` with `LazyColumn` (`220.dp`) listing up to `40` passages for the current book (chapter/paragraph `Snippet` + `Highlight`/`Bookmark`/`Text` badge, amber when priority), or graceful no-results (“No passages found… Try a different phrase — Folio searches highlights, bookmarks and text, all on-device.”). ## Performance — compose jank fixes (2026-09-12)

Investigated six common Compose performance patterns and fixed the real stalls (same output, less waste):

- **Library covers (Coil) — full-res decode on every recomposition** — `ui/library/components/BookCoverCard` now loads via `ImageRequest.Builder(...).size(440×660).memoryCacheKey/diskCacheKey + crossfade` downsampled to the `148.dp` grid cell instead of decoding the full cover bitmap on every recomposition. Re-scroll is instant from memory cache.
- **Highlight overlay re-parse on every frame** — `ui/reader/components/HighlightOverlay` now caches decoded strokes `remember(highlights)` (`DecodedHighlight` with norm/pressures/tilts/color) so `Canvas` only re-parses when the highlights list actually changes, not on every scroll/color animation frame.
- **In-book search LazyColumn missing stable key** — `ui/reader/ReadingScreen` in-book results `LazyColumn` now uses a stable `key = chapter-paragraph-matchType-hash` instead of index-only `items(size)`, avoiding full-item recomposition on insert.
- **Color triple-layer animation thrash (palette → adaptive → time tint)** — `ui/theme/AmbientLightSensor` now throttles `luxState` updates to perceptible changes (>5 lux or >2%) via EMA threshold, and `ui/reader/ReadingScreen` debounces `targetBg/targetText` (color distance >0.015) before `animateColorAsState (900ms)`, so sensor noise / minute-tick warmth no longer restarts a 60fps tween of the entire reading tree.
- **Synchronous disk I/O on main thread** — `data/cache/TruePageCache` / `ParsedBookCache` / `XRayCache` file reads/writes were on the composition/`viewModelScope(Main)` thread. Now: `ui/reader/TruePageEngine` loads via `runBlocking(Dispatchers.IO)` and saves fire-and-forget on `Dispatchers.IO`; `ui/reader/ReadingViewModel` wraps all `ParsedBookCache.load/save`, `XRayCache.isComplete/load/loadChapter/saveChapter`, and `EpubParser.parse` in `withContext(Dispatchers.IO/Default)`, and `ui/library/LibraryViewModel` invalidates caches inside `withContext(Dispatchers.IO)`. No `File.readText/writeText` on main.
- **Verified not stalling** — `TruePageEngine` / `KnuthPlassEngine` already correctly `remember`ed on `screenWidth/height/orientation/fontScale/density/bionic/chaptersKey/isTablet` (+ `configKey`/`bookId`/`fileHash` for TruePage) so scroll doesn't recompute; `BionicReading.toBionicAnnotated` already `remember(paragraph)` per paragraph; `LazyVerticalGrid BookGrid` already had `key = { it.id }`. No change needed — confirmed not being invalidated eagerly.

Behavior unchanged — only when/how work is scheduled.

## Concurrency & crash fixes (2026-09-12) — 50+ SAF books + bookmarks

- **Bookmarks single-bookmark bug:** see above — unique index + IGNORE allows many per book.
- **50+ SAF books crash:** `BookProcessingWorker` now throttled with `Semaphore(2)` (`withPermit`) so at most 2 books parse+X-Ray concurrently (was dozens of `Start processing` within ms → OOM / file contention). `ParsedBookCache`/`XRayCache`/`TruePageCache` writes are atomic (tmp → rename). `SearchRepository` uses `ConcurrentHashMap` for `chapterCache`, catches `OutOfMemoryError`/`Throwable`, and wraps per-book full-text in `try/catch` to skip a book still mid-processing rather than crash; `EpubParser` catches `OutOfMemoryError`/`Throwable` and GCs. Same result, no ANR/OOM on 50+ imports + concurrent search.
